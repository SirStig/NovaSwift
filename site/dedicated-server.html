Downloads

The NOVA Swift Dedicated Server is a small standalone program. It doesn't need the game, a pilot or any EV Nova data: it carries the session (rules, chat, moderation, plug-in checks) while each player's own game runs their ship. You manage it from a web admin panel in your browser.

Arriving with the next release. The standalone server is being finished now. Until its downloads appear below, you can host with the game's own headless mode: see Running a server today.

What it's built to do:

  • No game data. Nothing to copy onto the server; nothing copyrighted on your VPS.
  • Web admin panel on port 53737: players, kick and ban, rules, plug-ins from the catalog, public listing and logs. A setup wizard runs the first time.
  • Safe defaults. It works with no configuration. The admin password is generated on first start and printed once.
  • Easy networking. A built-in port check and optional UPnP, with errors in plain language.
  • Runs anywhere. Linux, Windows and macOS builds, a Docker image and a systemd unit.

Set it up

  1. Download and start it

    Unpack the download and start the server. On Windows, double-click it. On Linux or macOS, run it from a terminal. It starts with sensible defaults and prints the admin panel address and a one-time admin password.

  2. Open the admin panel

    Go to http://localhost:53737 on the same machine (on a desktop it opens by itself). From another computer use the server's address with port 53737. The setup wizard asks for a server name, player limit, rules and an optional join password.

  3. Choose the rules

    Safe: PvP damage and death aren't real, good for sparring. Full stakes: they are. Custom: pick PvP, real damage, friendly fire, permadeath and trading yourself.

  4. Add plug-ins (optional)

    Gameplay plug-ins on the server must match what players have enabled. Pick them from the community catalog so players can install the same ones with one click when they join. Art and sound plug-ins are optional for players.

  5. Open the ports and test

    See the next section. Then join from the game with the server's address.

Open the ports

PortProtocolWhat it's forOpen to the internet?
53735UDPThe game itselfYes, players need it
53736UDPStatus pings (server lists, player counts, latency) and LAN discovery. Game port + 1 if you change the game port.Yes, to show as online in server lists
53737TCPWeb admin panel (standalone server)No. Keep it on your own network, or reach it over SSH or a VPN

In your router's settings, forward UDP 53735 and UDP 53736 to the computer running the server. Or turn on UPnP in the server and let it ask the router (many routers have UPnP off).

Then give players your public address (search "what is my IP"). If your router's WAN address is different from that, or starts with 100.64 to 100.127, your provider uses carrier-grade NAT and forwarding can't work: use a VPS or Tailscale instead.

# ufw (Ubuntu, Debian, Raspberry Pi OS)
sudo ufw allow 53735:53736/udp

# firewalld (Fedora, RHEL)
sudo firewall-cmd --permanent --add-port=53735-53736/udp && sudo firewall-cmd --reload

Windows asks the first time the server starts: allow it on private and public networks. To add the rule yourself, in an administrator PowerShell:

New-NetFirewallRule -DisplayName "NOVA Swift server" -Direction Inbound -Protocol UDP -LocalPort 53735-53736 -Action Allow

A VPS already has a public address. Allow UDP 53735-53736 in the provider's firewall or security group as well as in the machine's own firewall (see the Linux tab). Don't open 53737; reach the admin panel through an SSH tunnel:

ssh -L 53737:localhost:53737 you@your-vps
# then browse to http://localhost:53737

Running a server today

Until the standalone server ships, the Linux build of the game can run headless as a dedicated server. It needs your EV Nova data on that machine (the folder the game imported, NOVA_DATA_DIR or --data), and it has a console instead of the web panel.

# from a source checkout
scripts/run-dedicated-server.sh --name "My Server" --port 53735 --max-players 8 --rules safe

# from the packaged Linux build
./NovaSwift --headless -- --server --config /path/to/server.cfg

Useful options: --password X, --rules safe|full, --no-lan, --upnp, --log FILE, --no-stdin (for services), and, with the script, --check, which prints your public address, warns about carrier-grade NAT and tests whether the server answers from outside.

Settings and console

Settings live in server.cfg; command-line flags override the file. An annotated example:

[server]
name="My NovaSwift Server"
port=53735
max_players=8
password=""
; safe | full | custom (custom reads [rules])
rules="safe"
lan=true
stdin=true

;[rules]
;base="safe"
;allow_pvp=true
;pvp_damage_real=false
;friendly_fire=false
;death_real=false
;allow_trade=true

Console commands (type them into the server window):

CommandDoes
statusName, port, players, rules
playersWho's connected
kick <id|name> [reason]Remove a player
ban <id|name>Remove and block a player
say <text>Message everyone
rules safe|fullSwitch the stakes
quitStop the server

Passwords. A join password is sent hashed, but game traffic isn't encrypted by default. Don't reuse a password that matters. Encrypted (DTLS) servers are in testing for Godot-only groups.

Keep it running

On Linux, a systemd service restarts the server if it stops and starts it at boot. Adjust the paths and user:

# /etc/systemd/system/novaswift-server.service
[Unit]
Description=NOVA Swift dedicated server
After=network-online.target

[Service]
User=nova
WorkingDirectory=/opt/novaswift
ExecStart=/opt/novaswift/NovaSwift --headless -- --server --config /opt/novaswift/server.cfg --no-stdin
Restart=on-failure

[Install]
WantedBy=multi-user.target
sudo systemctl enable --now novaswift-server
journalctl -u novaswift-server -f

No systemd? tmux or screen works too. A Docker image comes with the standalone server.

Get listed

The public server list is a JSON file in the NovaSwift-Plugins repository. Both the game's browser and this website read it. To add your server:

  1. Get your entry

    Start the server once with --public (plus --region, --owner, --contact, --description and --address if you have a domain). It prints a ready-to-paste JSON entry, including the content hash of every plug-in it requires. It never uploads anything.

  2. Add it to servers.json

    Fork the repository, paste the entry into the servers array of servers/servers.json, and check it with python3 servers/validate.py.

  3. Open a pull request

    Title it Add server: <name>. Once it's merged, your server shows up in the game's browser and on the server list.

Rules for listing: a public address (no 192.168.x.x), no passwords in the entry, honest rules labels, plug-ins players can get from the catalog, family-friendly names, and a contact. Servers that stay offline for a month or two may be removed. Until you're listed, players can join straight away with your address.

{
  "id": "example-eu",
  "name": "Example Sector",
  "host": "nova.example.com",
  "port": 53735,
  "region": "eu",
  "description": "Friendly 24/7 server, safe rules, stock EV Nova.",
  "owner": { "name": "Jane", "contact": "discord: jane" },
  "rules": "safe",
  "plugins": [],
  "maxPlayers": 12,
  "added": "2026-10-13"
}

Troubleshooting

Friends can't connect

Check UDP 53735 is forwarded to the right machine and allowed in its firewall. Test from outside your network (many routers can't loop back to their own public address), or run scripts/run-dedicated-server.sh --check. If your provider uses carrier-grade NAT, forwarding won't work: use a VPS or Tailscale.

The server shows as offline in lists but people can join

Status pings use UDP 53736 (game port + 1). Forward and allow that port too.

Players get "version" or "plug-ins" errors

Everyone needs a compatible game version and the same gameplay plug-ins as the server. The game lists what to install, disable or update. Cosmetic plug-ins don't count.

UPnP didn't work

Many routers ship with UPnP turned off, and it can't help behind carrier-grade NAT. Forward the ports by hand instead.
